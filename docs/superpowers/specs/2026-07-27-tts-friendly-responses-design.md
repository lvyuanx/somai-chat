# TTS 友好回复设计

## 目标

让 SOMAI 的所有回复都适合直接交给端侧 TTS 播放：内容简短、自然、口语化、纯文本，不输出来源、网址或复杂排版。

## 方案

采用提示词与输出规范化双层保障。

### 提示词约束

在稳定身份提示词中明确以下规则：

- 所有回复使用简短、自然、适合朗读的纯文本短句。
- 禁止 Markdown、表格、链接、网址、来源列表、代码块和装饰性符号。
- 搜索结果只能作为事实资料使用，不在最终回复中披露来源名称或网址。

删除运行时能力提示中要求列出搜索来源和网址的冲突规则。

### 输出规范化

扩展现有 `TextNormalizer`，在流式文本发送前移除模型意外生成的 Markdown 链接、裸网址和常见展示格式，同时保留链接文字和正文内容。规范化必须继续支持独立流式片段，不改变现有天气单位转换和事件协议。

## 测试

- 提示词测试确认禁止来源、网址和复杂格式。
- 规范化测试确认 Markdown 链接与裸网址不会出现在最终文本中。
- 保留现有流式片段、天气单位和图谱测试，运行完整检查命令。
