# 机器人后台与客户端凭证设计

## 目标

将 SOMAI 从单一调试 Chat 页面扩展为具身智能机器人的管理后台。管理员使用配置中的
`admin` / `123456` 登录；后台以深色石墨和宝石蓝为视觉基调，提供控制总览、客户端管理和
Chat 工作区。机器人客户端必须使用独立 Key 建立 WebSocket 连接。

首期不提供人工用户管理、消息正文持久化、Key 重叠轮换或客户端 Key 的浏览器输入界面。

## 架构与存储

新增独立 `admin` 模块，承载管理员会话、客户端和 Key 生命周期；WebSocket 路由只依赖其
认证结果，不直接处理 MySQL 查询。数据库使用 SQLAlchemy 2 异步 ORM 与 `asyncmy` MySQL
驱动；Alembic 管理版本化迁移。

首个迁移创建以下关系：

- `clients`：客户端 ID、名称、可选描述、启用状态、创建/更新时间和最后认证时间。
- `client_access_keys`：所属客户端、公开 Key ID、Key 摘要、到期时间、创建时间、最近使用时间与撤销时间。

一个客户端可以保留历史 Key 记录，但任何时刻只有一个未撤销、未过期的 Key。创建客户端或
轮换 Key 都生成新记录；轮换立即撤销旧 Key，不存在重叠窗口。停用或删除客户端会使其全部 Key
立即不可用于认证。

完整 Key 使用 `somai_sk_<key-id>_<random-secret>` 格式。数据库仅保存 `key-id` 和以集中
配置 Pepper 计算的摘要；完整 Key 仅在创建和轮换成功时返回一次，不写日志、不返回到后续列表或详情。

## 认证与接口

配置集中在 `core.Settings`：MySQL URL、管理员用户名/密码、管理员会话签名密钥和客户端 Key
Pepper。开发配置提供 `admin` / `123456`；生产配置拒绝该默认密码及占位签名/加密材料。

`/admin/login` 提供管理员登录页。成功登录创建签名的 `HttpOnly`、`SameSite=Lax` Cookie，
生产环境加 `Secure` 标记；管理 API 的写操作使用 CSRF 令牌校验。登录失败采用进程内按来源限流，
避免默认凭证被无限尝试。

新增版本化 `/api/v1/admin` 接口：登录、登出、当前会话、客户端分页列表/详情、创建、编辑、启停、删除
和 Key 轮换。所有管理业务接口在未认证时仅返回稳定的 401/403/404/409/422 响应，不暴露数据库或密钥信息。

机器人通过 WebSocket 握手头 `Authorization: Bearer <key>` 认证。管理员 Chat 从后台页面以管理员
会话 Cookie 认证，不需要客户端 Key。`/api/v1/chat/ws/{conversation_id}` 在 Origin 和运行时校验后，
要求两种认证方式之一；缺失、错误、过期、撤销或已停用的机器人 Key 以 1008 关闭且不说明失败原因。
机器人认证成功后只更新该客户端和 Key 的最近使用时间。

根路径进入后台；Chat 作为后台导航中的工作区。总览只显示可从客户端数据可靠得出的计数和最近活动，
不新增消息正文、模型回复或会话审计持久化。

## 验证与文档

测试先行覆盖：Alembic 升级、客户端 CRUD、Key 一次性展示、摘要存储、有效期、立即撤销和停用；
管理员 Cookie/CSRF/登录限流；管理员与机器人 WebSocket 认证，以及缺失、错误、过期、撤销和停用 Key
的 1008 关闭。浏览器测试覆盖登录、客户端管理、创建/轮换确认和后台内现有 Chat 协议状态机。

更新 `.env.example`、README、各受影响模块的 `AGENTS.md` 与打包测试，记录新增配置、MySQL 迁移步骤、
机器人的 Bearer 握手方式和后台入口。
