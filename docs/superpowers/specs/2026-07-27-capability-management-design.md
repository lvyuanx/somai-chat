# Admin 动态能力管理设计

## 背景与目标

SOMAI 当前在应用启动时根据环境变量装配天气、时间和联网搜索工具。管理员无法在运行期间查看、修改或关闭这些
能力，配置变化也需要修改部署环境并重启服务。

本功能在现有管理后台新增“能力管理”页面，以卡片形式管理以下三项能力：

- 查询天气
- 查询时间
- 联网搜索

管理员可以在单张卡片中编辑固定参数、开启或关闭能力，并通过“保存配置”一次性持久化。保存成功后不打断正在
生成的回复，同一 WebSocket 连接发送的下一条消息立即使用新配置。

首版不管理摄像头拍摄和视觉识图能力，也不提供任意键值参数或自定义能力注册。

## 已确认的产品行为

- 能力开关和参数保存在 MySQL 中，服务重启后继续有效。
- 每种能力使用固定字段和固定校验规则。
- 缺少必填参数时禁止开启能力，并明确显示缺失字段。
- 数据库尚无能力记录时，从现有环境变量导入一次；记录创建后环境变量不再覆盖数据库。
- API Key 默认脱敏，管理员可以通过眼睛按钮查看完整值。
- 未输入新 API Key 时保存会保留旧值；只有显式执行“清除 Key”才删除旧值。
- 卡片内的开关和字段修改先形成草稿，点击该卡片的保存按钮后才统一持久化和生效。

## 页面与交互

管理后台侧边栏在“客户端管理”和“Chat 工作区”之间新增“能力管理”。页面保持现有后台的深海蓝紫主题，桌面端
以三列展开式卡片展示能力，小屏降为单列。

每张卡片包含名称、说明、启用开关、固定参数、更新时间、卡片内错误和保存按钮。每张卡片独立维护草稿、保存状态
和错误状态；保存一张卡片不会锁定另外两张卡片。字段发生修改后显示未保存状态，保存期间禁用当前卡片的重复提交。
保存成功后刷新该卡片的服务端值并显示成功消息；保存失败时保留草稿和卡片内错误，避免管理员重新输入密钥以外的
配置。

字段如下：

| 能力 | 固定参数 | 说明 |
| --- | --- | --- |
| 查询天气 | API Host、API Key、请求超时 | API Key 为必填敏感参数 |
| 查询时间 | 无 | 固定使用 `Asia/Shanghai` |
| 联网搜索 | API Host、API Key、请求超时、最大结果数 | API Key 为必填敏感参数 |

API Key 输入区默认显示脱敏值和“已配置”状态。眼睛按钮按需调用 reveal API 获取明文；替换时使用密码输入框。
“清除 Key”需要明确操作，清除后如果能力仍处于开启草稿状态，保存校验会阻止提交。

## 持久化模型

新增 `capabilities` 表，每种能力一行，以稳定字符串标识 `weather`、`time` 和 `web_search`。表保存：

- 能力标识
- 启用状态
- 非敏感固定配置 JSON
- 加密后的 API Key，可空
- 创建时间和更新时间

API 层和能力服务使用分能力的 Pydantic 模型校验 JSON 内容；数据库 JSON 不是任意扩展入口。天气配置固定为
`api_host` 和 `timeout_seconds`，时间配置固定为空对象，联网搜索配置固定为 `api_host`、`timeout_seconds` 和
`max_results`。敏感值不写入非敏感 JSON。

API Key 使用 `SOMAI_CAPABILITY_SECRET_ENCRYPTION_SECRET` 提供的独立密钥进行认证加密，生产环境禁止缺失或使用
占位值。列表响应只包含脱敏值和是否可查看，不包含密文或明文。

首次应用初始化时，在一个事务中补齐缺失能力行：

- 天气：从现有 QWeather 环境配置导入；配置完整时保持当前可用状态并启用。
- 时间：创建为启用状态，无参数。
- 联网搜索：从现有 Tavily 环境配置导入；存在 API Key 时启用，否则以关闭状态创建。

初始化只插入缺失行，不更新已有行，因此后续重启不会用环境变量覆盖在线修改。

## Admin API

所有接口位于现有 `/api/v1/admin` 前缀下，沿用管理员 Cookie 会话和 CSRF 保护。

### 获取能力列表

`GET /api/v1/admin/capabilities`

返回三项能力的标识、显示信息、启用状态、非敏感配置、API Key 脱敏值、是否可以查看和更新时间。列表接口只要求
管理员会话，不返回任何完整密钥。

### 保存单项能力

`PUT /api/v1/admin/capabilities/{capability}`

请求固定包含 `enabled` 和完整 `configuration`，可选包含新的 `api_key`，并以默认值为 `false` 的
`clear_api_key` 表示明确清除。非空 `api_key` 与 `clear_api_key=true` 互斥；请求没有携带新 Key 且未要求清除时保留
已有 Key。时间能力拒绝 `api_key` 和清除指令。

服务端先合成保存后的完整配置并校验，再开启数据库事务。启用天气或联网搜索时，最终配置必须包含 API Host、
API Key 和有效的数值参数。事务提交成功后，能力目录发布新快照。响应返回更新后的脱敏视图。

### 查看 API Key

`POST /api/v1/admin/capabilities/{capability}/api-key/reveal`

接口要求管理员会话和 CSRF。没有已保存 Key、解密失败或能力不支持 Key 时返回安全错误，不泄露密文或内部异常。

### 错误语义

- 未知能力返回 404。
- 字段格式、范围、互斥关系或缺少启用必填配置返回 422。
- 未登录或 CSRF 无效沿用现有 Admin API 行为。
- 持久化或解密异常只返回安全消息；日志不得记录密钥、完整 URL 或供应商原始响应。

## 动态运行时架构

应用启动时创建一个进程内能力目录。目录从数据库加载三项能力，并持有当前不可变快照。快照包含启用能力对应的
轻量工具对象及已经校验的参数，不拥有 HTTP 连接生命周期。

每轮消息开始时，`ConversationRuntime` 从能力目录读取一次当前快照，并把它放入本轮 LangGraph 配置。模型节点只
绑定快照中启用的工具，因此关闭的能力不会继续暴露给模型。工具节点也只执行同一快照中的工具，保证一次模型调用
和后续工具调用不会混用两个配置版本。

保存能力时先构造并验证候选快照，再提交数据库事务，随后原子替换目录中的当前快照。正在运行的一轮继续持有旧
快照，下一轮读取新快照。这一设计保持现有对话图、内存 Checkpointer、线程锁和 WebSocket Session 不变，不丢失
已有会话历史，也不需要重建 Runtime。

天气和搜索工具的快照使用应用统一拥有的 `httpx.AsyncClient`。适配器把 API Host、API Key、超时和结果数作为快照
参数传入请求，不为每轮消息或每次保存创建新的连接池。HTTP 客户端只在应用关闭时释放。

摄像头工具不属于管理范围，继续始终注册。视觉分析能力继续沿用现有启动配置，不受本页面影响。

## 一致性与并发边界

- 能力保存以单行数据库事务完成，读者不会看到半套参数。
- 候选配置在事务前完成纯校验，事务提交后发布对应内存快照。
- 当前项目为单进程部署，进程内原子快照满足运行时一致性；本设计不声明多实例同步能力。
- 同一能力的并发保存采用数据库行锁串行化，后提交的完整卡片配置生效。
- 活跃生成不因管理操作取消；“立即生效”明确指保存后的下一条消息。

## 前端模块边界

能力页实现为独立 Vue 组件，不把卡片状态和 API 逻辑继续堆入 `App.vue`。现有 `App.vue` 已超过仓库建议的 500 行
上限，本次在保持行为不变的前提下，提取与页面职责相符的管理组件，使后台壳只负责认证、导航和页面组合。能力
卡片的字段描述和草稿转换使用独立、可测试的模块，避免在模板中复制保存与校验逻辑。

## 测试策略

所有实现遵循测试先行：先观察目标测试因能力尚未实现而失败，再编写最小实现使其通过。

后端测试覆盖：

- Alembic 迁移和模型结构。
- 首次环境变量导入，以及已有数据库记录不被重启覆盖。
- API Key 加密、脱敏、查看、替换和清除。
- 三项能力的固定字段校验，以及缺少必填配置时禁止开启。
- Admin API 登录、CSRF、404、422 和安全错误响应。
- 每轮只绑定当时启用的工具，保存后的下一轮读取新快照。
- 正在执行的一轮保存旧快照，且对话历史和线程隔离不受切换影响。
- HTTP 客户端由应用统一关闭，不因刷新快照泄漏资源。

前端测试覆盖：

- 服务端能力视图到单卡草稿的转换。
- 未输入新 Key 时保留旧值，替换与清除指令互斥。
- 单卡保存中、成功、失败保留草稿和缺少配置提示。
- 能力管理导航、三张卡片和响应式布局存在于构建产物。

验收命令包括前端生产构建、JavaScript 测试、Python lint、严格 mypy 和完整 pytest 测试套件。
